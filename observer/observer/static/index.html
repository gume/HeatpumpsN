Database export and import

Export writes the recorded samples into one compact file (Parquet with zstd, about 2 bytes per sample; DuckDB, pandas and others read it directly). Import adds the samples of such a file that the database does not have yet: a sample counts as present when the same signal has a sample at the same time, so importing a file twice, or a file that overlaps the database, never duplicates anything. Nothing is ever deleted or overwritten.

The observer's state (registry, house understanding, library, model settings, house context; no secrets, no recorded data) moves separately: export here, import on the other observer (it replaces those files there and keeps the old ones in backup/).

How the observer understands the house, in three parts: your review (free text, any time), the owner knowledge consolidated from your reviews (facts that are not in the sensor data) and the house understanding built from the data and that knowledge. A new draft of both waits for your acceptance; accepting archives knowledge, understanding and your review together (house/ in the data directory, not in git). Analyses and the agent use the accepted version.

Corrections, missing facts, answers to the questions, comfort targets, changes in the house. Any language, any form: it is consolidated into the owner knowledge when you generate a draft.

The agent answers questions about the house from the recorded data. It decides itself which data and time windows it needs: the code it writes runs in a sandbox without network and reads the database through the run's read-only data socket. It uses the library's tools and skills (see Library, with audit flags) and can add new, unaudited ones. It never changes the plant or the database: proposals are for you to decide. Every run is kept with its steps, code, data queries and report in runs/ of the data directory.

The controller's predictive mixer control uses a model per pump scenario (the mixing law, the transport delay and two sensor lags). The observer re-identifies it from live data (daily, or now) and compares it with the current set on held-out data that was not used for fitting. Only a clearly better model becomes a proposal. Nothing reaches the controller without your approval; the controller checks every set against its compiled limits, and every sent set keeps the one it replaced for a roll back.
